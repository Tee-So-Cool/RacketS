# เทียบไม้แบด (ใช้เอง)

เว็บเทียบไม้แบด เอ็น ลูกแบด รองเท้า ถุงเท้า และจับคู่ไม้+เอ็น เป็นไฟล์ static ไม่ต้อง build ฝั่งเว็บ

ใช้งานจริง: https://tee-so-cool.github.io/RacketS/

## หน้าในเว็บ

| เส้นทาง | หน้า | ทำอะไร |
|---|---|---|
| `#rackets` | ไม้แบด | เทียบได้ทีละ 3 รุ่น: เรดาร์ แถบเทียบ ตารางสเปก "เหมาะกับใคร" และรุ่นที่คล้ายกัน |
| `#hot` | ไม้น่าสนใจ | จัดอันดับจากสเปก (ไม่ใช่ยอดขายหรือรีวิว) ไม่นับปีจากแคตตาล็อกที่ยังไม่มีแหล่งยืนยัน |
| `#strings` `#shuttles` `#shoes` `#socks` | เอ็น ลูกแบด รองเท้า ถุงเท้า | เทียบแบบเดียวกับไม้ |
| `#match` | จับคู่ไม้+เอ็น | คะแนน 0-100 แสดงปอนด์แนะนำเมื่อมีเพดานยืนยันครบและเลือกเวตแล้วสำหรับไม้หลายเวต |
| `#manage` | จัดการข้อมูล | เพิ่ม แก้ ทำสำเนา ลบ Export Import (เก็บใน localStorage) |

## เปิดใช้ในเครื่อง

```bash
cd /Users/tee/MyPro/RacketS && python3 -m http.server 8765
```

แล้วเปิด http://localhost:8765

## ข้อมูล

ไฟล์แคตตาล็อกใน `data/*.js` **สร้างจากสคริปต์ อย่าแก้ตรง ๆ** ตัวเลขทุกค่าต้องมีแหล่ง ค่าที่ประเมินเองถูกใส่ใน `est` และเว็บแสดงเป็น "(ประเมิน)" ห้ามเดาสเปก ราคา หรือปี

เครื่องหมาย `≈` ใช้กับค่าที่ประเมินและปีเดิมที่ยังไม่มี `yearSrc` เมื่อตรวจพบว่าปีเดิมผิดและยังหาปีจริงไม่ได้ ให้ใช้ `"year": null` ในไฟล์ override เพื่อเว้นปีไว้ สเปกที่มีเฉพาะจุดสมดุลเป็น mm จะจัดประเภทหัวหนักหรือหัวเบาแบบประเมิน เพดานเอ็นจากหลายหน้าที่ให้ค่าต่างกันจะแสดงเป็นค่าประเมินจนกว่าจะตรวจแหล่งที่ระบุค่าตรงรุ่นได้

```
scripts/sources/*.json   ข้อมูลดิบจากแหล่งต่าง ๆ (chobbad, Yonex, Badminton Plaza, ร้านค้า, เว็บผู้ผลิต)
data/spec-overrides.json สเปกที่หาเองทีละรุ่น มี src ทุกรุ่น (ไม้)
data/string-overrides.json, data/shuttle-overrides.json  เหมือนกัน สำหรับเอ็นและลูกแบด
scripts/build_*.py       รวมทุกอย่างเป็น data/*.js
data/catalog-v1.js       ข้อมูลอ้างอิงจากแคตตาล็อกเก่า โหลดเฉพาะตอนย้ายข้อมูลในเบราว์เซอร์
```

สร้างข้อมูลใหม่:

```bash
python3 scripts/build_rackets.py
python3 scripts/build_strings.py
python3 scripts/build_shuttles.py
python3 scripts/build_gear.py      # รองเท้า และถุงเท้า
```

ดึงข้อมูลดิบใหม่ใช้สคริปต์ `scripts/fetch_*.py` (ยิงไม่เกิน 1 request ต่อวินาที ห้ามหลบ rate limit หรือ Cloudflare)
ถ้า `fetch_shops.py` ดึงร้านใดไม่ครบ สคริปต์จะเก็บข้อมูลชุดล่าสุดของร้านนั้นไว้ พร้อมแสดงชื่อร้านที่ต้องลองใหม่
ขั้นตอนหาสเปกทีละรุ่นอยู่ใน `.claude/skills/racket-spec-lookup/SKILL.md` โน้ตค้นคว้าอยู่ใน `docs/research/`

งานค้นคว้ารอบใหม่ใช้ [รูปแบบหลักฐานรายค่า](docs/research/research-quality-pilot.md#นำเข้าหลักฐาน) เพื่อเก็บรหัสสินค้า ตลาด เวตและลิงก์ต้นทาง รัน `python3 scripts/merge_research.py <หลักฐาน.json>` เพื่อดูผลก่อนบันทึก แล้วใช้ `--apply` เพื่อบันทึกไฟล์ `data/racket-research.json` ตัว build จะใช้หลักฐานที่ยืนยันได้ตามขอบเขตของแต่ละค่า

รัน `python3 scripts/research_queue.py` เพื่อดู [คิวตรวจสเปกรุ่นใหม่](docs/research/research-quality-pilot.md#คิวตรวจสเปกรุ่นใหม่) และลิงก์สำหรับหาเพดานเอ็นตามเวต รหัสสินค้า เวต และปีที่ยังต้องยืนยัน

ใช้ [แคตตาล็อก Yonex](https://www.yonex.com/badminton-catalog) สำหรับเทียบสเปกตามรหัสสินค้า และใช้ประกาศเปิดตัวสำหรับปีวางขาย สำหรับ Li-Ning ใช้ [แคตตาล็อก FUNPORT](https://funport.co.jp/pdf/funport2026.pdf) และ [หน้าสินค้าของ FUNPORT](https://order.funport.co.jp/view/category/badminton_racket_lining) ตรวจรุ่นน้ำหนักก่อนบันทึกเพดานเอ็น ระบุ `tensionByWeight` และ `tensionSrc` เมื่อแหล่งระบุแต่ละรุ่นน้ำหนักชัดเจน

ใช้ [คลังไม้ BadmintonCN](https://www.badmintoncn.com/cbo_eq/list.php?class=1) ในเบราว์เซอร์ เลือกแบรนด์และซีรีส์ แล้วเปิดหน้ารุ่นจากรายการ ถ้าหน้ารุ่นเปิดไม่ได้ ให้ค้น `site:badmintoncn.com/cbo_eq "ชื่อรุ่น"` ตรวจชื่อและรหัสรุ่นก่อนบันทึกค่าที่ระบุชัดใน `data/spec-overrides.json` พร้อมลิงก์รายรุ่นใน `src` หรือ `yearSrc` แล้วรัน `python3 scripts/build_rackets.py` วันที่ `上市日期` คือวันที่วางขายตามที่ BadmintonCN ระบุและอาจต่างจากตลาดอื่น

หากต้องการข้อมูลทั้งคลัง ให้สอบถามช่องทางส่งออกหรือ API กับ [ฝ่ายประสานงาน BadmintonCN](https://www.badmintoncn.com/about/contact.html) ผลค้นหาครอบคลุมเฉพาะหน้าที่ถูกจัดทำดัชนี

เพิ่มรุ่นไว้ใช้เองผ่านแท็บ "จัดการข้อมูล" แล้วกด Export เพื่อสำรองหรือย้ายไป Import ในเบราว์เซอร์อื่น ใช้ไฟล์จากหมวดเดียวกัน
เบราว์เซอร์เก็บเฉพาะรายการส่วนตัวแล้วรวมกับแคตตาล็อกล่าสุด เว็บจะเทียบข้อมูลแบบเก่ากับแคตตาล็อกในอดีตตอนเปิดครั้งแรก และเก็บสำเนาเดิมให้ดาวน์โหลดจากปุ่ม Export ชุดเดิม
ถ้าต้องการเพิ่มรุ่นบนเว็บที่ deploy ให้แก้ไฟล์ override สำหรับหมวดนั้นและรันสคริปต์ build ตามด้านบน GitHub Actions สร้างไฟล์ `data/*.js` ใหม่ทุกครั้งที่ deploy

## ทดสอบ

```bash
node tests/run.js
python3 -m unittest discover -s tests
```

ทดสอบคะแนนจับคู่ เรดาร์ ไม้น่าสนใจ บันทึกส่วนตัว การนำเข้า และการเก็บข้อมูลเดิมเมื่อดึงข้อมูลร้านพลาด ไม่ต้องติดตั้งไลบรารีเพิ่ม
เปิด `tests/match.html` ผ่านเซิร์ฟเวอร์ในเครื่องเพื่อดูผลในเบราว์เซอร์ได้เหมือนกัน เคสอยู่ใน `tests/cases.js`
ผลตีจริงที่เคยลอง ใส่ใน `tests/feedback.js` แล้วจะกลายเป็นเคสทดสอบความตึงที่แนะนำ

## Deploy

push เข้า `main` แล้ว GitHub Actions (`.github/workflows/pages.yml`) จะ build ข้อมูลใหม่ รันเทสต์ แล้วขึ้น GitHub Pages ถ้าเทสต์ไม่ผ่านจะไม่ deploy

## หมายเหตุ

- ราคาเป็นค่าประมาณ ควรเช็กกับร้านก่อนซื้อ
- กราฟบุคลิกไม้และคะแนนจับคู่คำนวณจากสเปก สูตรอยู่ใน `app.js` (`racketProfile`, `score`)
- ปีที่ออกของไม้ยังขาดเกือบ 70% (VS, Felet, Hundred ไม่มีเลย) ค้นด้วยเว็บทั่วไปแล้วไม่เจอปีที่ยืนยันได้ จึงปล่อยว่างแทนการเดา
